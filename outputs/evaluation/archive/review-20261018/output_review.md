# Archive output content review

Review date: 2026-10-18. This is a local content and provenance review of the **14 pre-retry outputs that were both JSON parsed and schema compliant**, identified in `outputs/evaluation/archive/retry-20261018/before-selected-runs.json`. The exact selected `run.json` paths are captured in the accompanying `output_review.json`; each output is the adjacent `archive.json`. This snapshot intentionally excludes any later retry result.

The archive evaluator selects the newest run for each document/model by file modification time (`folklore_eval/evaluate.py::evaluate_archive`). It reports request completion, JSON parsing, and schema validity; it does not assess whether extracted values are supported or complete. `config/archive.schema.json` checks structure and types, while `config/prompt_archive_v2.txt` requires source-only extraction, complete cleaned text, and careful distinction between contributor and collector. As `challenges.md` already records, archive outputs are not the region benchmark contract and no benchmark accuracy values can be derived from this review.

## Findings from the sampled outputs

**Schema-validity does not resolve content and field-boundary questions.** Thailand's one-page source has romanization, word-level gloss, and English rendering. Its prepared OCR/input and PDF text layer contain noise, including `mutual aly`, `ony /3u/#/`, and `14` among the source lines. The selected Gemini medium output puts OCR-corrupted lines in `folklore.item` and gloss/English rendering in `translation`; Haiku puts romanization, gloss, and English sentence together in `item` and repeats the English sentence in `translation`; Sonnet keeps the romanization in `item` and gloss/English in `translation`. That Sonnet division may be consistent with the prompt; the confirmed issue is inconsistent handling across outputs and OCR noise, while deciding the ideal division requires clearer annotation rules. Examples: [Gemini Thailand archive.json](../../../runs/archive/evaluation/gemini_flash/00002_56_Thailand_Folkspeech__38/2168615a7810b3fb8b055c56a7d3d4ba6d672da52aca63a2bc183f8fa5b235af-retry-20261016T071033948647Z/archive.json), [Haiku Thailand archive.json](../../../runs/archive/evaluation/haiku/00002_56_Thailand_Folkspeech__38/0ad2828a259f4fd96b2ee90fcfcce8b01b6893cfafbbd43d1fd826fdfc2e6b10-retry-20261016T071019283407Z/archive.json), [Sonnet Thailand archive.json](../../../runs/archive/evaluation/sonnet/00002_56_Thailand_Folkspeech__38/75327cb5dab26ccdc0ded49a84d0dcb62c538254c43748a773f7d1ec80e09fef-retry-20261016T071012963247Z/archive.json), and source [PDF](../../../../JSONs/Thailand%20Folkspeech.pdf).

**Contributor/collector roles need a field-level human decision on Thailand.** The OCR text begins “Myself, Age 21. Female” and later says “This is a description I learned from my father, Boonlert Nakkeow.” The selected Gemini medium, Haiku, and Sonnet outputs respectively set `collector.name` to “Varinthorn Nakkeow,” null, and “Varinthorn Nakkeow.” The evidence identifies Varinthorn as narrator/contributor and Boonlert as the person from whom she learned the expression; it does not explicitly name a separate collector. Whether a first-person narrator should also populate `collector` is a schema semantics question, not a settled extraction error. Do not normalize this mapping without deciding what “collector” means for first-person records.

**Attribution can be placed differently even when the source supports the wording.** Anglo Folkspeech identifies Thinh Nguyen as informant and Jon Tai Tran as collector. Sonnet copies the passage beginning “I agree with his interpretation. Even though some believe that wisdom grows with age...” into `collector.collector_comments`; Haiku leaves that field null. The source does include the collector's first-person interpretation, so this is not unsupported content. The question is whether that passage belongs in collector comments or `analysis.interpretation`. The prompt distinguishes these fields but does not completely specify the boundary. See [Sonnet Anglo archive.json](../../../runs/archive/evaluation/sonnet/00003_Anglo_Folkspeech_VI_A67_C6__74/3d73667821146b4a53f7d4ed5bd1c402e51abb8e0154ff18c4eb2f27c8ace5d3-retry-20261016T071106665678Z/archive.json) and [source PDF](../../../../JSONs/Anglo%20Folkspeech%20VI.pdf).

**The saved OCR itself contains suspect text.** Turkey's source text layer says `English, Turkish, Erench`; all four selected schema-valid Turkey outputs preserve `Erench` in `contributor.languages_spoken` rather than silently correcting it to French. This is faithful to the supplied OCR text, but I did not inspect page pixels to confirm whether the original says “French.” The text layer also includes artifacts such as `[rect]` and split proverb words. Example: [Turkey PDF](../../../../JSONs/Turkey%20Proverbs.pdf), [Sonnet Turkey archive.json](../../../runs/archive/evaluation/sonnet/00002_86_Turkey_Proverbs_III__147/0617b4bfeb81befcd42e34509b277b25a270501cf5c837e850914625a0f3bd6f-retry-20261016T070756291593Z/archive.json).

**Place assignment needs a consistent rule.** Turkey's source prose says Defne first heard the proverb from her friend's mother “in Ayvalik, Turkey,” while describing the proverb's history/use. Sonnet puts Ayvalik, Turkey in `folklore.place_mentioned`; Gemini medium, Haiku, and Gemini high use `[]`. The source mentions the place, but whether provenance context counts as a place “mentioned in the folklore” is a policy decision, so the disagreement is not scored here as a definite omission. The source gives Berkeley, California as the collection location; selected outputs put that in `location_collected`.

**Exact Thailand field excerpts show the item/translation split.** The OCR text layer has `sam/wan/dee/`, `see / wan / khai/`, `three /day /good/`, `four/ day / fever/`, and `Good for three days and fevered for four days.` Gemini medium places corrupted OCR fragments including `mutual aly` in `folklore.item` and uses `three /day /good/ —_four/ day / fever/ Good for three days and fevered for four days.` as `translation`. Haiku's `folklore.item` contains the romanization, gloss, and English sentence, while its `translation` repeats `Good for three days and fevered for four days.` Sonnet puts only the romanization in `item` and the gloss plus English sentence in `translation`. This supports a field-boundary and OCR-quality review; it does not establish which Thai romanization is correct.

**Full-text fields are close in size but still need completeness and OCR alignment checks.** For example, using the same source PDF text layer, the Vietnam Legend source text is 8,853 characters (spaces joined between pages) while selected Gemini medium and Sonnet `cleaned_full_text` are 8,741 and 8,721 characters. That size difference alone does not prove omitted content because whitespace and normalization differ; however, the text field is specifically required to reconstruct the full document. A reviewer should compare normalized token sequences or page-by-page OCR, and inspect the ending and transitions, rather than use length as an accuracy proxy. The Taiwan outputs also differ in whether extracted location fields contain San Jose, California, even though the source header gives that as collection location; Haiku leaves the location object entirely null-valued while Gemini and Sonnet fill it. See each model's Taiwan records in the run inventory.

Across documents, schema-valid outputs routinely populate `country: null` for California collection locations, which is acceptable because the schema permits unknown components. The prompt's allowed age bucket `45-4` is explicitly ambiguous; outputs leave the Taiwan and Vietnam contributor buckets null despite ages appearing in source (53 and 53). This is prudent under the prompt and should not be counted as an omission without a corrected bucket definition.

## Review needed before annotation accuracy work

1. **Confirm OCR/source text first.** Inspect page images for noisy or ambiguous OCR, especially the Thailand romanization and Turkey `Erench`; record source transcription corrections separately from model extraction judgments.
2. **Set field-level annotation rules.** Decide how to map narrator/contributor vs collector in first-person entries; whether collector interpretations/comments belong in `collector.collector_comments` or `analysis`; whether translations/glosses belong in `folklore.item` or `translation`; and whether places in explanatory provenance count as `place_mentioned`.
3. **Create a gold archive annotation or adjudicated checklist.** The user's existing benchmark annotations are region labels/boxes, not field-level labels for this archive schema. They cannot directly score these nested archive fields, and this report does not invent benchmark values.
4. **Score completeness and fidelity field by field.** Include exact source support, missed facts, fabricated/inferred facts, full-text coverage, duplicate content across fields, and contributor/collector attribution. Have a second reviewer adjudicate ambiguous mappings.
5. **Control run conditions before model comparison.** Of the 14 selected valid outputs, 13 used `max_tokens=16,384`; only Taiwan Gemini medium used `65,536`. The higher cap was part of the successful selected retry. Prompt hash is shared in the saved records, but token caps and transport settings vary across the run history. Compare accuracy only with aligned input, prompt, generation, and retry conditions, and preserve the pre-retry snapshot when reporting.

## Limits

This is a qualitative review with representative concrete examples, not a full double-annotated audit. I inspected all 14 selected JSON objects and compared representative disputed text and provenance fields against the local PDF text layer/prepared OCR. This was an OCR/text-layer review only; I did not visually inspect PDF page images. Schema compliance is taken from the saved pre-retry run metadata. Text extraction cannot resolve image/OCR ambiguity; page-image review remains necessary. No model accuracy score, ranking, or accuracy graph is produced here.
